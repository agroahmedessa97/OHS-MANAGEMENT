# منصة HSE متعددة الشركات — نسخة تجريبية

**هذه نسخة اختبار وليست جاهزة إنتاجيًا أو ضمانًا أمنيًا.**

## طريقة الدخول المطلوبة
- مدير الشركة ينشئ شركة: اسم الشركة، اسم المدير، اسم المستخدم، البريد (فريد)، كلمة المرور (10 أحرف أو أكثر).
- Worker يولد كود شركة فريد (HSE-...) ويعيده للمدير.
- المدير يدخل بكود الشركة واسم المستخدم وكلمة المرور.
- المدير يضيف الأعضاء: اسم، اسم مستخدم، بريد (فريد عالميًا)، كلمة مرور، دور (member أو manager).
- الموظف يسجل الدخول باستخدام كود الشركة واسم المستخدم وكلمة المرور.
- كل طلب API محمي يتحقق من العضوية، والاستعلامات تسند الشركة إلى معرف الشركة من جلسة موثقة، وليس من العميل.
- قاعدة البيانات تفرض uniqueness على email وusername وcompany_code.

## Cloudflare
1. أنشئ D1 database.
2. نفذ schema.sql على قاعدة D1.
3. أنشئ R2 bucket (التخزين غير موصول بالواجهات في هذه النسخة).
4. عدّل database_id في wrangler.toml.
5. أضف secret JWT_SECRET عشوائيًا قويًا وOPENAI_API_KEY.
6. نشر Worker عبر Wrangler.
7. استضف HTML على Pages أو اختبره محليًا. أدخل عنوان Worker في واجهة HTML واحفظه.

## نقاط ناقصة قبل الإنتاج
- استعادة كلمة المرور بالبريد والتحقق من البريد ليست مفعلة (تحتاج مزود بريد وإجراءات token آمنة).
- R2 لم يتم ربط endpoints رفع/تنزيل المستندات.
- وحدات النظام HTML الأصلية لم يتم ربط جميع نماذجها بهذه API؛ هذا ملف اختبار مستقل للواجهة.
- الاختبار الأمني، tenant-isolation test، rate limits، allow-list origins، CSP، إدارة الجلسات، وMFA مطلوب.
- Worker يتيح AI text/images (حتى 8 صور) عند ضبط OPENAI_API_KEY. راجع التكلفة وحدود الملفات.
